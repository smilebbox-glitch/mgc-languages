# Automotive Manufacturing Workspace — v4.0.0

## Цель

MGC Engineering AI остаётся единым engineer-only сервисом, но инженерный проект теперь можно смотреть в контексте конкретной производственной зоны автомобиля. Отдельные приложения для каждого цеха не создаются: используется один проект, один Digital Thread и один простой переключатель **«Зона»**.

## Встроенные производственные зоны

- R&D / Инжиниринг продукта;
- Штамповка;
- Кузов / Сварка;
- Окраска;
- Сборка;
- Компоненты;
- Логистика;
- Качество;
- Технология производства / Industrialization;
- Испытания / Валидация.

Список зон задан как стабильная automotive taxonomy для пилота. Зона может быть отключена для конкретного проекта, иметь владельца и отдельные SSO/ACL-группы.

## Как работает контекст

Каждый загружаемый документ может иметь `manufacturing_area`. Если пользователь предварительно выбрал рабочую зону в UI, она передаётся при загрузке автоматически. В карточке документа зону можно изменить или оставить документ **общим для проекта**.

Внутри зоны сервис показывает:

- относящиеся к ней детали и документы;
- общие проектные документы, которые нужны как контекст;
- открытые validation issues;
- активные ECR/ECO;
- Design Review;
- milestones;
- BOM/assembly context;
- readiness gates и блокеры.

Документные ACL остаются сильнее Project/Area ACL. Выбор зоны не расширяет доступ к скрытому документу.

## Area-aware AI / RAG

При выборе зоны `manufacturing_area` передаётся в RAG-запрос. Qdrant фильтрует evidence по зоне до генерации ответа. Это снижает смешивание, например, логистической и сварочной документации в одном ответе.

Для поиска по ещё не классифицированным legacy-документам пользователь может выбрать **«Все зоны»**.

## Automotive focus checklist

Для каждой зоны UI показывает короткий рекомендательный фокус. Примеры:

### Кузов / Сварка
- материал и толщина;
- сварные соединения и обозначения;
- базы / fixture points;
- доступность соединений и оснастки;
- ECR/ECO, влияющие на кузовную геометрию.

### Окраска
- coating/surface requirements;
- маскирование;
- совместимость материалов и покрытий;
- полости/дренаж;
- surface quality issues.

### Сборка
- BOM completeness;
- интерфейсы и посадочные размеры;
- крепёж/момент/последовательность;
- tooling/ergonomics;
- impact изменений на сборочную операцию.

### Логистика
- масса и габариты;
- упаковка и защита;
- маркировка/traceability;
- material flow / sequence;
- влияние изменения на тару и маршрут.

Эти пункты — **advisory checklist**, а не автоматически пройденные требования и не разрешение на выпуск.

## UX-принцип

Чтобы не перегружать пользователя:

1. основной sidebar не расширяется списком цехов;
2. в header находится один компактный selector **«Зона»**;
3. внутри Project Workspace — один горизонтальный switch зон;
4. технические настройки ACL/SSO остаются в admin/API;
5. пользователь видит только текущий контекст и следующее действие.

## Безопасность

- сервис остаётся Engineer-Only;
- все human-facing API требуют `get_identity`;
- ProjectArea может иметь отдельные ACL groups;
- area selection не является authorization bypass;
- model server / API / DB / Qdrant не публикуются наружу;
- document ACL проверяется независимо от project/area membership.
