# Drawing Activity Timeline — v3.5

## Что сохраняется

Для каждого инженерного документа ведётся отдельная история действий. Автоматически фиксируются, в частности:

- загрузка документа;
- открытие карточки и preview;
- разбор чертежа;
- Drawing ↔ 3D linking;
- VLM-проверка;
- поиск геометрических аналогов;
- конвертация КОМПАС/T-FLEX и создание производной;
- вопрос к Engineering AI, если документ вошёл в evidence ответа;
- Design Review;
- изменение статуса инженерного замечания;
- ручная запись инженера «что сделано / проверено / решено».

Каждое событие содержит пользователя, UTC timestamp, действие, понятное описание и структурированные детали.

## Защита целостности

История append-only на уровне приложения: публичных API для изменения или удаления старых событий нет. События образуют SHA-256 цепочку: `event[n]` содержит hash `event[n-1]`. Отдельная запись `DocumentActivityState` хранит последний hash и количество событий — поэтому обнаруживается в том числе удаление самой новой записи. На PostgreSQL запись сериализуется блокировкой документа, чтобы параллельные действия инженеров не создавали разветвление цепочки. При чтении сервис пересчитывает всю цепочку, сверяет anchor и показывает статус целостности.

Это **tamper-evident**, а не абсолютная защита от привилегированного DBA: пользователь с полным доступом к БД и приложению теоретически может переписать и пересчитать цепочку. Для регулируемого production рекомендуется дополнительно экспортировать audit events в корпоративный immutable/WORM SIEM или журнал с внешней подписью.

## Что видит инженер

В карточке документа есть блок **«История работы с документом»**:

```text
✓ Целостность истории подтверждена

04.09.2026 14:20  ivan.petrov
Полная проверка конструкции

04.09.2026 14:12  maria.sokolova
Проверен размер Ø10 — замечаний нет

04.09.2026 13:58  ivan.petrov
Вопрос Engineering AI: почему изменён кронштейн?
```

Инженер может добавить заметку одной из категорий: `Что сделано`, `Проверка`, `Решение`, `Вопрос`, `Другое`. Старые записи через UI/API не редактируются.

## Retention

По умолчанию audit retention настроен на длительное хранение. Перед production срок хранения, экспорт в SIEM и правила удаления должны быть согласованы с IT/InfoSec и требованиями компании.
