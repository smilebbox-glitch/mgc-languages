# Automotive Area Pilot Acceptance — v4.0.0

Минимальный пилот рекомендуется провести на одном автомобильном проекте и минимум трёх зонах, например **Кузов/Сварка + Окраска + Сборка**.

## Test data

Подготовить:

- 2–5 деталей на каждую зону;
- CAD + drawing минимум для одной детали каждой зоны;
- один общий project requirements документ;
- один общий BOM;
- по одному issue/ECR для двух разных зон;
- минимум один milestone на зону.

## Acceptance cases

1. Пользователь выбирает `Сварка`; в списке деталей нет paint-only детали.
2. Общий project requirements остаётся доступным как project evidence.
3. AI-запрос в контексте `Сварка` не использует paint-only evidence.
4. При загрузке файла в выбранной зоне файл получает эту зону автоматически.
5. Зону существующего документа можно изменить из карточки; событие появляется в tamper-evident history.
6. Workspace `Окраска` показывает собственные counts/issues/changes/milestones.
7. Area focus для каждой зоны соответствует automotive context и явно помечен как advisory.
8. Пользователь без ACL конкретной ProjectArea не может открыть её workspace или назначить туда документ.
9. Доступ к ProjectArea не раскрывает документ, закрытый document ACL.
10. Переключение `Все зоны` восстанавливает полный разрешённый инженерный контекст проекта.

## Production gate

Перед rollout IT/R&D должны согласовать:

- какие зоны реально используются на заводе;
- mapping корпоративных SSO groups на area ACL;
- owner каждой зоны;
- правила классификации legacy-документов;
- какие zone-specific проверки являются advisory, а какие позже должны стать формальными release gates.
