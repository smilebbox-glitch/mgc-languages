# Pilot KPI Definition — v6.0.6

Default acceptance targets are deliberately explicit and can be tightened by the corporate pilot board.

| KPI | Default target | Gate class |
|---|---:|---|
| Required scenario coverage | 100% | Critical |
| Required role coverage | 100% | Critical |
| Scenario success rate | >=95% | Critical |
| Evidence coverage | 100% | Critical |
| High/Critical blockers | 0 | Critical |
| Median task-time reduction | >=30% | Conditional |
| Average usability rating | >=4.0/5 | Conditional |
| Aggregate UX telemetry sessions | >=10 | Critical |
| Aggregate UX error rate | <=2% | Conditional |

Task-time comparisons must use the same scenario definition before/after MGC. Do not compare different tasks, different engineering maturity states or different data availability and call the result a productivity gain.

The pilot should additionally record qualitative facilitator categories such as `navigation`, `evidence_clarity`, `data_gap`, `workflow_fit`, not free-text employee assessments.
