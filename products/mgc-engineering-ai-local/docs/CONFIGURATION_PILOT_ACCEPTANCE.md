# Pilot Acceptance — Vehicle Variant & Configuration Management v4.8

Пилот рекомендуется провести на одном автомобильном проекте минимум с тремя вариантами.

## Набор

Создать, например:

1. EU / 1.5T / AT / Luxury;
2. RU / 2.0 / MT / Base;
3. ещё один вариант без настроенной применимости.

## Проверки

1. Одну деталь явно включить в Variant A.
2. Эту же деталь явно исключить из Variant B.
3. Variant C оставить без applicability.
4. Убедиться, что impact показывает A = affected, B = excluded, C = unknown.
5. Создать interface и привязать его к Variant C; проверить косвенное влияние.
6. Затем явно исключить part из Variant C и подтвердить, что явное исключение имеет приоритет.
7. Создать ECR по детали и выполнить impact analysis; убедиться, что UI показывает затронутые варианты.
8. Проверить скрытый evidence другой ACL-группы — конфигурация не должна просачиваться в workspace.
9. Проверить режим производственной зоны и All Areas.
10. Выполнить `docker compose build`, `make dockle`, `make acceptance` на корпоративном build-host.

## Критерий приёмки

- неизвестная применимость никогда не интерпретируется как included;
- ECR/ECO показывает variant impact;
- ACL не ослабляется конфигурационным слоем;
- обновление v4.7 → v4.8 не требует чистой базы;
- интерфейс не получает нового основного раздела.
